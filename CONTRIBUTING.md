# Руководство для контрибьюторов и AI-агентов (Contributing to SIMEMU)

Перед внесением любых изменений ознакомьтесь с обязательными архитектурными правилами в `AGENTS.md`, картой крейтов и
контрактами подсистем в `ARCHITECTURE.md` и текущим проверенным состоянием в `MILESTONE.md`.

---

## 1. Незыблемые инженерные инварианты (Core Rules)

1. **Zero-Patch (`AGENTS.md` §2.1)**
   - Код прошивок исполняется побайтно без изменений.
   - Запрещены патчи инструкций, принудительная запись в RAM прошивки со стороны хоста, подмена регистров/PC, пропуск
     функций или обход проверок мониторинга/иммобилайзера/контрольных сумм.
   - Любая проверка со стороны прошивки (PLL, WDT/ENDINIT, PMU/Flash, ADC/FADC, MultiCAN, SSC/DMA/MSC, ATIC139 MU/LS/PS,
     ATIC140/121/111, ATIC142, PIC12LF1822, ST95640, WFS5) удовлетворяется **исключительно** эмуляцией аппаратных
     регистров, внешних микросхем, электрических цепей и шины CAN.
   - Единственные документированные исключения уровня программатора/лабораторного NVM перечислены в `AGENTS.md` §2.4.

2. **Zero-Fake-Logic (`AGENTS.md` §2.2)**
   - Rust моделирует только физику (`simemu-physics`, `simemu-acoustics`) и электрику/периферию плат (`simemu-tc1791`).
   - Все решения управления (дроссель, УОЗ, впрыск DI/MPI, ТНВД N276, вестгейт, фазовращатели, AVS, реле, стартер,
     передачи, давления сцеплений, насос мехатроника) принимают **только прошивки**.
   - На границе `EcuOutputs` / `TcuOutputs` значение `None` всегда означает обесточенный силовой каскад (разомкнутую цепь).
   - Отказы деталей возникают только из физических законов нагружения, трения, теплообмена и усталости материалов —
     сценарные отказы запрещены.

3. **Доказательность и реверс-инжиниринг (`AGENTS.md` §2.3)**
   - У каждого утверждения о поведении прошивки или аппаратуры должен быть проверяемый источник: адрес в образе,
     идентификатор доказательства REA (`ev_…`), трасса исполнения (`VERIFIED-T`), страница Funktionsrahmen (`FR p.N`),
     даташит (`VERIFIED-DS`) или воспроизводимый тест.
   - Инженерные оценки физических параметров без паспортных данных помечаются `UNVERIFIED` и выносятся в публичные поля
     конфигурации (`*Hw`, `*Profile`), а не в «магические константы» внутри формул.
   - Статический реверс бинарных образов прошивок при работе с AI-агентами выполняется через MCP-сервер `rea` на
     ELF-образах из `scripts/make_elf.py`.

## 2. Границы модулей (Black-Box Architecture)

Крейты разделены по строгим границам ответственности (`ARCHITECTURE.md` §1.1, §2):

| Слой | Крейты | Правило изоляции |
| :-- | :-- | :-- |
| **Ядро CPU** | `tricore-core`, `unicorn-tricore-sys` | Не знают о конкретных платах SIMOS18/DQ200/DQ250; общаются с периферией только через типаж `tricore_core::Bus` или колбэки Unicorn. |
| **Платы и периферия** | `simemu-tc1791` | Моделирует MCU (TC1791, TC1784, TC1766) и ASIC на платах. **Не зависит** от `simemu-physics`: принимает напряжения/фронты/кадры `CanFrame` и отдаёт электрические состояния выводов. |
| **Физика и звук** | `simemu-physics`, `simemu-acoustics` | Чистый Rust без C-зависимостей и без знания об адресах RAM/регистров прошивок. Принимает `PlantActuators` + `DriverInputs` + `BenchMode`, возвращает `PlantTelemetry` и физические сигналы датчиков. |
| **Калибровки и шина** | `simemu-damos`, `simemu-bridge` | Кодеки DAMOS, пересчёт контрольных сумм CRC/ECM3, генератор кадров rest-bus шасси MQB (`MqbChassisEncoder`). |
| **Интеграция и UI** | `simemu-cli` | Стыкует выводы плат с физикой (`studio::io`, `io_air`, `tcu_io`), ведёт lock-step окно 1 мс (`StudioSession`), веб-интерфейс Studio (`127.0.0.1:8080`) и TCP-сервер Lawicel/SLCAN (`127.0.0.1:28750`). |

## 3. Настройка окружения разработчика

### Автономная разработка чисто-Rust крейтов (без Unicorn и без дампов прошивок)

Для работы над `tricore-core`, `simemu-physics`, `simemu-acoustics`, `simemu-damos` или `simemu-bridge` достаточно
установленного `rustup` (`rustc` ≥ 1.88):

```sh
cargo clippy -p tricore-core -p simemu-physics -p simemu-acoustics -p simemu-damos -p simemu-bridge --all-targets
cargo test --release -p tricore-core -p simemu-physics -p simemu-acoustics -p simemu-damos -p simemu-bridge
```

### Полная сборка workspace и SIL-тесты с прошивками

1. Создайте `.venv` и установите `unicorn==2.1.4` (или соберите патченую библиотеку `python scripts/build_unicorn.py` —
   см. `README.md`).
2. При наличии собственных дампов и контейнеров `.frf` поместите их в локальный каталог `vault/firmwares/` (подробная
   структура папок описана в `README.md`) или укажите путь через `SIMEMU_IMAGE_DIR`.
3. Всегда запускайте эмуляционные тесты с `--release` (в `debug` интерпретация сотен миллионов инструкций кратно
   медленнее).

## 4. Чек-лист перед коммитом / Pull Request

- [ ] **Соблюдение правил:** нет нарушений `Zero-Patch` и `Zero-Fake-Logic`, нет `.unwrap()` на внешних/гостевых данных,
      нет аллокаций на горячих путях (шаг 0.2 мс физики, кванты CPU/GPTA, поток аудио).
- [ ] **Линтер и сборка:** `cargo clippy --workspace --all-targets --all-features` проходит без предупреждений, а
      `cargo check -p simemu-cli --no-default-features` подтверждает сборку минимального CLI.
- [ ] **Тесты и детерминизм:** `cargo test --release` проходит; дайджесты `perf_determinism` (`simemu-tc1791`) не
      меняются без явного аппаратного обоснования; при изменениях в контуре проверены сценарии `boot_regression`,
      `power_stages_e2e` и затронутые сценарии `scripts/run_scenarios.sh`.
- [ ] **Гигиена репозитория:** `git diff --check` чист; в коде, скриптах и документации нет личных локальных путей
      (`/Users/...`, `C:\Users\...`, `~/Downloads`), секретов и сторонних бинарных дампов прошивок.
- [ ] **Документация:** при добавлении модулей или изменении контрактов обновлены `ARCHITECTURE.md` и `MILESTONE.md`.
