> каналов АЦП (§3.2) уточнены и исправлены в актуальном справочнике `docs/DQ200_IO_MAP.md`. Разделы §6–§7 описывают ранние
> эксперименты с записью в RAM прошивки (такой подход запрещён правилом Zero-Patch `AGENTS.md` §2.1 и в коде отсутствует),

## 0. Критический баг приёма CAN-фреймов (`MOFCR.DLC`) в `Tc1791HardwareState::inject_can_rx` (`crates/simemu-tc1791/src/memory.rs:175`)

До этого исправления прошивка `DQ200_G2` **отбрасывала 100% входящих CAN-фреймов** (`0x013` ответ иммобилайзера `WFS5`, `Motor_*`, `ESP_*`, `Klemmen_Status_01` и т.д.) из-за отсутствия записи поля `DLC` в регистр `MOFCR`:
- **Причина**: В `DQ200_G2` функция инициализации `can_init_mo` (`0x800E5FC0`) настраивает все приёмные Message Objects с `MOFCR = 0x0000_0000` (`DLC = 0`). При приёме кадра драйвер `can_poll_rx` (`0x800E6C20`) вызывает `can_read_rx_mo` (`0x800E6394`), которая читает фактический `DLC` принятого кадра из байта `+0x03` регистра `MOFCR` (`0xF000_5000 + mo_idx * 0x20 + 0x03`, т.е. биты `MOFCR[27:24]`):
  ```asm
  0x800e63c8: ld.bu d15, [a6]       ; a6 = mo_base + 3 (MOFCR bits [31:24])
  0x800e63ca: and   d15, #0xf       ; d15 = принятый DLC
  0x800e63cc: min.u d2, d15, #8     ; d2 = число копируемых байт и возвращаемое значение
  ```
- Поскольку `inject_can_rx` в `memory.rs` записывал только `MODATAL` (`+0x10`), `MODATAH` (`+0x14`) и `MOSTAT` (`+0x1C`) без обновления `MOFCR.DLC` (`+0x00`), функция `0x800E6394` читала `DLC = 0`, копировала **0 байт**, а `0x800E6C20` (`0x800E6C74`) выставляла флаг ошибки несовпадения DLC (`[desc+5] |= 0x08`, `[desc+4] = 0`).
- **Исправление в `crates/simemu-tc1791/src/memory.rs:195` (`inject_can_rx`)**:
  ```rust
  let mofcr = self.read_f000_u32(mo_base);
  let dlc = (frame.dlc.min(8) as u32) & 0xF;
  self.write_f000_u32(mo_base, (mofcr & 0xF0FF_FFFF) | (dlc << 24));
  ```

### 1.2. Побитовая структура `Getriebe_11` (`0x0AD`, Packer `0x800CC032`, Staging `0xD000_78A8..0xD000_78AF`)
- **`buf[0]` (`0xD000_78A8`)**: **MQB CRC-8** (`0xF0` при `BZ = 1`).
- **`buf[1]` (`0xD000_78A9`)**:
  - `bits [3:0]`: **4-битный счётчик `GE_11_BZ`** (`0xD000_6FF7`, `1` в `0xE1`).
  - `bits [7:4]`: **`GE_Zielgang` (Целевая передача)**:
    - Упаковывается в `0x800CC0CE..0x800CC126`:
      - Если `*(uint8_t *)0xD000_78FF != 0` или `*(int8_t *)0xD000_7D40 == -2` или `*(uint8_t *)0xD000_77BE == 12`, принудительно выставляет **`0xE` (`14` = Error / Invalid / Locked)**!
      - Иначе переводит `*(int8_t *)0xD000_7D40` (`Zielgang`: `0=N, 1..7=1..7, -1=R`) по таблице `0x8013_9DC4` (`[1(R), 0(N), 2(1st), 3(2nd), 4(3rd), 5(4th), 6(5th), 7(6th), 8(7th)]`).
      - **Почему `buf[1]` был равен `0xE1`**: `*(uint8_t *)0xD000_78FF == 1` (выставлялся в `0x800C40DC` из-за бита ошибки датчиков `(*(uint8_t *)0xD000_7C46 >> 4) & 1 != 0`), поэтому `GE_Zielgang = 0xE` (`14`), что вместе с `BZ = 1` даёт **`0xE1`**!
- **`buf[2..3]` (`0xD000_78AA..0xD000_78AB`, 16-bit LE `0xFFBF` = байты `BF FF`)**:
  - `bits [9:0]` (`buf[2]` + `buf[3][1:0]`): **Момент сцепления / ползущего режима (`10-bit`, `0x3FF = 1023` = Invalid/Init)** из `*(int16_t *)0xD000_7F2C` и `*(uint8_t *)0xD000_7F31`.
  - `bits [11:10]` (`buf[3][3:2]`): **Статус сцеплений (`K1/K2`)** из `*(uint8_t *)0xD000_7F31` (`0..3`).
  - `bits [15:12]` (`buf[3][7:4]`): **`GE_Istgang` (Текущая включённая передача)**:
    - Упаковывается в `0x800CC136..0x800CC184`:
      - Если `*(uint8_t *)0xD000_78FF != 0` или `*(uint8_t *)0xD000_77BE == 12`, принудительно выставляет **`0xF` (`15` = Error / Notlauf / Init)**!
      - Иначе переводит `*(int8_t *)0xD000_7D42` (`Istgang`: `0=N, 1..7=1..7, -1=R`) по таблице `0x8013_9DD0`.
- **`buf[4..5]` (`0xD000_78AC..0xD000_78AD`, байты `00 04`)**:
  - `buf[4]`: бит 0 = `0xD000_7900 & 1`, бит 1 = `0xD000_7BC4` (флаг активного переключения), биты `[3:2]` = `0xD000_7CC2`, биты `[7:4]` = `0xD000_7BC0`.
  - `buf[5]`: биты `[1:0]` = `0xD000_78FA`, биты `[7:2]` = **6-битный момент потерь (`Verlustmoment`)** из `*(int16_t *)0xD000_7F2E`.
- **`buf[6..7]` (`0xD000_78AE..0xD000_78AF`)**: `0xD000_7D46` (6 бит) и `0xD000_7CC4` (10 бит).

### 1.3. Побитовая структура `Getriebe_12` (`0x0AE`, Packer `0x800CC204`, Staging `0xD000_78B0..0xD000_78B7`)
- **`buf[0]` (`0xD000_78B0`)**: **MQB CRC-8** (`0x6B` при `BZ = 1`).
- **`buf[1]` (`0xD000_78B1`)**:
  - `bits [3:0]`: **4-битный счётчик `GE_12_BZ`** (`0xD000_6FF8`).
  - `bits [7:4]`: **Режим вмешательства в момент ДВС (`MM_Momenteingriff`)** из `*(uint8_t *)0xD000_7BCC` (`0` = без вмешательства).
- **`buf[2..3]` (`0xD000_78B2..0xD000_78B3`)**:
  - `buf[2][3:0]`: **Положение селектора (`GE_Waehlhebelposition`)** (`0x800CC2B0..0x800CC2FA`):
    - Читает `*(uint8_t *)0xD000_77BE` (маппится через `0x8013_9DDE`; если `0xD000_78FD != 0`, выдаёт `0xD` или `0xC`).
  - `buf[2][5:4]`: биты режима (`0xD000_77BF` / `0xD000_77C3`).
  - `buf[3][7:4]`: **Индикатор передачи на приборке** (`0x800CC36C..0x800CC3D6` из `*(int8_t *)0xD000_7D44` через `0x8013_9DF6`).
- **`buf[4..5]` (`0xD000_78B4..0xD000_78B5`)**:
  - `buf[4][3:0]`: статус из `0x800BB52A()` (`1` при `0xD000_7906 == 0`).
  - `buf[4][7:4]` + `buf[5][5:0]`: 10-битный быстрый запрос момента (`*(int16_t *)0xD000_7BCE`).
- **`buf[6..7]` (`0xD000_78B6..0xD000_78B7`, 16-bit LE `0x01FD` = байты `FD 01`)**:
  - `bits [9:0]`: **10-битный лимит момента ДВС (`MM_Sollmoment`)** (`0x800CC20E..0x800CC284` из `0xD000_7BD0`; при `0xD000_7BCC == 0` равен `509 = 0x01FD` = пассивное значение без ограничения).
  - `bits [15:10]`: флаги статуса (`0xD000_78FE`, `0xD000_7F18` бит авторизации `WFS5`, `0xD000_77C3`, `0xD000_7902`, `0xD000_7901`).

## 3. Полная карта 36 каналов АЦП (`0xD000_B0A4..0xD000_B0EB`), датчиков вилок/давления/сцеплений и оборотов валов (`G182/G501/G502`)

### 3.1. Буфер АЦП (`0xD000_B0A4`) и причина ошибок по напряжению при записи `0x0564` / `0x0400`
- **Структура буфера**:
  - `uint16_t ADC[0..35]` по адресам **`0xD000_B0A4..0xD000_B0EB`**
  - `uint16_t ADC_INV[0..35]` по адресам **`0xD000_B0EC..0xD000_B133`** (`ADC_INV[i] = ADC[i] ^ 0xFFFF`, проверяется при каждом чтении в `0x800ED348(ch)`!).
- **Масштабирование напряжений питания (`0x800ED970`, таблица `0xD000_34AC` из Flash `0x8013_EC4C`, проверка в `0x800E6540`)**:
  - Формула в `0x800ED970`: `mV = (((5000 * gain) >> 12) * ADC[ch] + 256) >> 9`.
  - **Почему ранее возникали ошибки по питанию и опорному напряжению 5В**:
    1. **`KL30` (`ADC[20]` @ `0xD000_B0CC`) и `KL15` (`ADC[13]` @ `0xD000_B0BE`)** используют `gain = 0x0805` (`4.8945 мВ/LSB`).
       - `0x800EB988` / `0x800EC1F0` проверяют сырой код `ADC[20] >= 0x052F` (`1327`), **А ТАКЖЕ** `0x800E65A8` проверяет масштабированное напряжение в окне **`8000..17000 мВ` (`8.0..17.0 В`)**, **А ТАКЖЕ** `0x800E0060` проверяет `KL30 > 9000 мВ` и `KL15 > 9000 мВ`!
       - Запись `ADC[20] = 0x0564` (`1380`) давала всего **`6755 мВ` (`6.75 В < 8.0 В`)**, вызывая ошибку низкого напряжения `7`!
       - **Точное сырое значение для `13.85 В` (`13850 мВ`)**: **`0x0B0E` (`2830`)**!
    2. **Опорные напряжения 5В датчиков Холла `V_ref1` (`ADC[1]` @ `0xD000_B0A6`) и `V_ref2` (`ADC[19]` @ `0xD000_B0CA`)** используют `gain = 0x0247` (`1.3887 мВ/LSB`).
       - `0x800E6584..0x800E6592` проверяют масштабированное напряжение в окне **`4500..5500 мВ` (`4.5..5.5 В`)**!
       - Кроме того, `0x800E66E8` нормирует все ратиометрические датчики по формуле `norm_adc = (0x0E08 * ADC[ch]) / ADC[1 или 19]`.
       - **Точное сырое значение для `5.00 В` (`5000 мВ`)**: **`0x0E08` (`3592`)**!

### 3.3. ШИМ-датчики хода сцеплений (`G617` K1 / `G618` K2) — структуры захвата `0xD000_9C04`
- Читаются в `0x800F1720` через `0x800E3564(ch)` и `0x800E381C(ch)` для каналов `ch = 0, 1` (`G617` K1 комплементарная пара) и `ch = 2, 3` (`G618` K2 комплементарная пара) в массив **`uint16_t PWM_DUTY[0..3]` по адресу `0xD000_B294..0xD000_B29B`** (проверяются в `0x800EDAD8` на условие `PWM_DUTY[0] + PWM_DUTY[1] ≈ 10000` и `PWM_DUTY[2] + PWM_DUTY[3] ≈ 10000`).
- Каждый канал захвата `ch` (`0..3`) использует 20-байтную структуру по адресу **`0xD000_9C04 + ch * 0x14`**:
  - `+0x00` (`uint32`): период в тиках (`period`, например `10000`);
  - `+0x04` (`uint32`): длительность импульса (`high_time`, например `2000` для `ch=0,2` и `8000` для `ch=1,3`);
  - `+0x10` (`uint8`): байт статуса — бит 0 = `1` (валидный сигнал), бит 2 = `0` (нет таймаута), т.е. **`0x01`**!
  - Глобальный байт разрешения захвата GPTA по адресу **`0xD000_9C00`** должен быть равен **`0x01`**.

### 3.4. Датчики частоты вращения валов (`G182` входной вал, `G501` вал 1, `G502` вал 2)
- Читаются в `0x800D3ED8..0x800D4450` (и `0x800EE278`) через `0x800E4658(ch, &period, &pulse_cnt)`:
  - **`G182` (Входной вал КПП / Обороты ДВС)**: канал `8` -> период в `0xD000_B2EC` / `0xD000_7DCA`, итоговые **обороты входного вала (`uint16`, RPM)** по адресу **`0xD000_7DE2`** (и `0xD000_7520`).
  - **`G501` (Первичный вал 1 — нечётные передачи 1/3/5/7)**: канал `11` (`0x0B`) -> период в `0xD000_7536` (`uint32`), статус в `0xD000_7546` (`uint8`), итоговые **обороты вала 1 (`int16`, RPM)** по адресу **`0xD000_7DD6` / `0xD000_7CE8`**.

### 4.1. Архитектура `WFS5` в `0CW300043H_0002` на CAN ID `0x012` (TX) / `0x013` (RX)

  - `c7p` (`0x80047AE8`): **`01 02 03 04 05 06 07`**
  - `c7a` (`0x80047CE8`): **`08 09 0A 0B 0C 0D 0E`**
  - Байт санкции `S`: **`0x1F`** (бит 0 = 1 — пуск и замыкание сцеплений разрешены).

### 4.3. Точный алгоритм Zero-Patch ответа виртуальной приборки (`fpke`) в `0x013` на запрос `0x012`
Когда `DQ200_G2` передаёт кадр **`0x012`** (`MO[8]`, 8 байт `chal[0..7]`):
1. **Извлечь 4-байтный случайный вызов `P[0..3] = chal[0..3]`**:
   - *(Проверка подписи запроса `chal[4..7]` по формуле п. 2.2 из `fpke-immo-wfs5.md`)*:
     - `block_req = [0x9C, 0xF7, 0xFE, 0xB7, 0x5C, P[0], P[1], P[2], P[3], 0x01, 0x02, 0x03, 0x04, 0x05, 0x06, 0x07]`
     - `ct_req = AES128_ECB_Encrypt(K_tcu, block_req)` (`0x8004E7F8`)
     - `c[0..3] = CRC32_IEEE(ct_req).to_le_bytes()` (`0x8004E932`)
     - `chal[4..7] == [c[0], c[1], c[2] ^ 0xC1, c[3] ^ 0x85]`
2. **Вычислить 8-байтный ответ приборки `0x013` (`resp[0..7]`, инъекция в `MO[7]`) по формуле п. 2.4 из `fpke-immo-wfs5.md`**:
   - Побитовая инверсия вызова: `not_P = [P[0] ^ 0xFF, P[1] ^ 0xFF, P[2] ^ 0xFF, P[3] ^ 0xFF]`
   - Входной 16-байтный блок `AES-128-ECB`:
     - `block_ans = [0x9C, 0xF7, 0xFE, 0xB7, 0x5C, not_P[0], not_P[1], not_P[2], not_P[3], 0x08, 0x09, 0x0A, 0x0B, 0x0C, 0x0D, 0x0E]`
   - Шифрование **AES-128-ECB** ключом `K_tcu` (`EEPROM[0x01E9..0x01F8]`):
     - `ct_ans = AES128_ECB_Encrypt(K_tcu, block_ans)`
   - Стандартный IEEE **CRC32** (Little-Endian) от `ct_ans`:
     - `a[0..3] = CRC32_IEEE(ct_ans).to_le_bytes()`
   - Сборка 8-байтного кадра `0x013` (`DLC = 8`, `ID_ac = [0xD3, 0x2E]`, `S = 0x1F`):
     - `resp = [a[0], a[1], a[2] ^ 0xD3, a[3] ^ 0x2E, 0x00, 0x00, 0x00, 0x1F]`
   - Благодаря тому, что виртуальная приборка (`fpke`) отвечает моторнику `SIMOS18.1` (`0x010 -> 0x011`) его ключом, а коробке `DQ200_G2` (`0x012 -> 0x013`) — её собственным ключом из `ST95640 EEPROM`, **оба блока проходят 100% нативную криптографическую авторизацию WFS5 (Zero-Patch), несмотря на то, что дампы слиты с двух разных автомобилей Skoda Octavia A7**!

## 5. Полная 7-блочная таблица `ST95640 EEPROM` для `WFS5` (`0x01E8..0x02D3`) и передача управления `CBOOT -> ASW`

Декомпиляция цепочки инициализации иммобилайзера (`0x8004_70A4 -> 0x8004_9F68 -> 0x8004_A21E -> 0x8004_A4C8 / 0x8004_B770 / 0x8004_B65E -> 0x8004_A514`) выявила точное распределение всех 7 блоков EEPROM и механизм передачи маркера `CBOOT`:

### 5.1. Магическое слово `CBOOT -> ASW` (`0xCAFE_AFFE` @ `0xD001_FF38`)
- В `0x8004_70C0` вызывается `0x800E_874A(&0xD000_09C0)`, которая читает `*(uint32_t *)0xD001_FF38` (область обмена `CBOOT -> ASW` в конце `DSPR`), копирует 4 байта в `0xD000_09C0` и выставляет `0xD000_09F3 = 1`, `0xD000_09F4 = 1`.
- В `0x8004_A240` прошивка проверяет:
  ```c
  if (*(uint32_t *)0xD000_09C0 == 0xCAFEAFFE) { ... }
  ```
- Запись `0xCAFE_AFFE` в `0xD001_FF38` и `0xD000_09C0` подтверждает корректный переход из загрузчика `CBoot_V0006`.

## 6. Главный конечный автомат мехатроника (`0x800D_53A2..0x800D_63C0`, состояние `0xD000_7EC0`) и `KL15` / CAN Wake

Декомпиляция главного супервизора питания и гидравлики (`0x800D_53A2`, таблица переходов `switch(0xD000_7EC0)` по адресу `0x800D_5BC8` / `0x8013_A27C`) раскрыла полную последовательность пробуждения мехатроника:

1. **Контроль диапазона напряжения Клеммы 15 (`KL15`, `0x800D_4CA4..0x800D_4D5A`)**:
   - Функция `0x800D_4C70` проверяет отфильтрованное напряжение `KL15` в `[0xD000_760E + 0x28]` (`0xD000_7636`, канал 6 = `ADC[22]`, единицы `0.01 В`, норма `1385 = 13.85 В`) по порогам из `0x8002_6094`:
     - При `7.00 В <= KL15 <= 16.50 В` устанавливается **`0xD000_7E54 = 2`** (`KL15 Normal Operating Band`).
   - Затем `0x800D_5498..0x800D_54F6` при `0xD000_7E54 >= 2` и отсутствии флага аварии `0xD000_7EA1 == 0` выставляет **`0xD000_7EA8 = 2`** (`KL15 Active`).
2. **Контроль активности шины CAN (`0x800B_E58C..0x800B_E632`)**:
   - Функция `0x800B_E58C` вызывает `0x800E_8768(&local)` (которая проверяет **`*(uint8_t *)0xD001_FF48 == 1`**) и смотрит на `0xD000_7EA8`:
     - Если на первом такте до вызова `0x800D_5498` байт `0xD000_7EA8 < 2`, то `0x800B_E608` вычисляет `(dspr[0x6F75] != 1) + 1 = 2` (`CAN Bus Sleep`) и записывает `2` в **`0xD000_6F75`**.
     - Из-за `0xD000_6F75 == 2` ветка `case 1` (`0x800D_5C3C`) немедленно переводила главный автомат `0xD000_7EC0` в состояние **`0x0E` (`14 = Power-Down / Shutdown`)**, что блокировало обработку селектора!
   - Инициализация `0xD001_FF48 = 1`, `0xD000_6F75 = 1`, `0xD000_7E54 = 2`, `0xD000_7EA8 = 2` гарантирует безошибочное прохождение всех стадий `0xD000_7EC0`:
     - `1 (Init)` -> `2 (CAN Wake)` -> `3 (Pre-Check)` -> `4 (Sensor Check)` -> `5 (Hydraulics Ready)` -> **`8 (Normal Running)`** (`0xD000_7EA3 = 1`).

## 7. Двустороннее рукопожатие селектора КПП `Wählhebel_03` (`0x0AF`) <-> `Getriebe_16` (`0x128`)

Декомпиляция функций `0x8007_1CF4`, `0x8007_2692` и `0x8007_2F92` показала, как именно мехатроник `DQ200_G2` защищает переключение режимов `P / R / N / D / S`:

1. **Приём `Wählhebel_03` (`0x0AF`, `MO[20]`, `DLC = 4` согласно таблице `0x8013_968C`)**:
   - В `0x8013_968C` (`0x8013_9560 + 25 * 12`) дескриптор `MO[20]` (`0x0AF`) имеет `DLC = 4` (`04 00 AF 00 ...`). В `MultiCAN+` функция `inject_can_rx` использует `DLC = 4` для `0x0AF`, чтобы проверка `DLC` в `0x800E_6BE4` не отвергала кадр.
   - Распаковщик `0x800F_18C4` извлекает:
     - `0xD000_7336 = (byte[0] >> 4) & 0x0F` (`5 = D, 6 = N, 7 = R, 8 = P, 12 = S`);
     - `0xD000_7338 = (byte[1] >> 4) & 0x0F` (инвертированный ниббл `~sel & 0x0F`, то есть `0x0A` для `D`).
2. **Взаимная проверка с `Getriebe_16` (`0x128`) в `0x8007_2692` и `0x8007_2F92`**:
   - В калибровках `0CW300043H` по адресу `*(0xD000_CC24) + 0x52 = 0x8003_E452` записана `1` (включена защита селектора через `Getriebe_16` `0x128`).
   - Функция `0x8007_2692` вызывает `0x8007_2F92`, которая проверяет флаги `0xD000_5283 == 0` и `0xD000_5284 == 0`:
     - Когда оба флага равны `0`, `0x8007_2F92` вызывает:
       - `0x8007_23FE(uVar3)` -> записывает `5` (`D`) в **`0xD000_5244`** (`raw_selector_d8`);
       - `0x8007_240A(uVar3)` -> обновляет внутренний индекс селектора;
       - `0x8007_2800(uVar3)` и `0x8007_2860(uVar3)` -> переводят `5` (`D`) по таблице `0x8002_1FE8` в код `GE_Waehlhebel = 8` (`D`) и записывают его в **`0xD000_5250`** и **`0xD000_524F`** (откуда он копируется в `0xD000_6966` и уходит в `Getriebe_11` `0x0AD`).
     - Сброс `0xD000_5283 = 0`, `0xD000_5284 = 0`, `0xD000_5251 = 0` при инъекции датчиков мехатроника обеспечивает мгновенное принятие селектора `P / R / N / D / S` (`raw_selector_d8 = 5`, `waehlhebel_code = 8`, `selector_fault = 0x00`).

## 8. Физическая модель Skoda Octavia A7 FL 1.8 TSI (`CJSA` + `IS12` + `DQ200_G2` + `225/40 R18 ET51`) и условия разрушения ДВС

> **Примечание (исторический раздел):** модули `thermodynamics.rs`, `cockpit_solver.rs` и `diagnostics.rs`, упомянутые ниже, были удалены при переходе на строгую физическую модель без сценарных порогов отказа (см. актуальные модули `crates/simemu-physics/src/{engine,cylinder,combustion,thermal,lubrication,driveline,vehicle,materials}.rs` и `ARCHITECTURE.md` §2.2).

В ранних модулях `crates/simemu-physics/src/thermodynamics.rs`, `crates/simemu-physics/src/cockpit_solver.rs` и `crates/simemu-physics/src/diagnostics.rs` была реализована первоначальная параметризованная модель автомобиля:

1. **Атмосфера и психрометрия (`-35..+45 °C`, `-100..5000 м`, по умолчанию `+5.0 °C` и `156 м` — Москва)**:
   - Барометрическая формула МСА с температурной поправкой + уравнение Бака (1981/1996) для парциального давления водяного пара и плотности влажного воздуха $\rho_{\text{air}}$.
2. **6-узловая термодинамика (Woschni + `N493` ITM + восковой термостат + `NTU-ε` радиатор + вентилятор `V7/J293`)**:
   - Отдельные теплоёмкости днища поршней (`piston_crown_temp_c` + масляные форсунки `N522`), ГБЦ с выпускным коллектором `IEM` (`cylinder_head_temp_c`), блока цилиндров (`engine_block_temp_c`), рубашки ОЖ (`coolant_temp_c`), радиатора (`radiator_coolant_temp_c`) и поддона масла (`oil_temp_c`).
   - Управление ШИМ-вентилятором радиатора `V7 / J293` (`0..100%`) со стороны `SIMOS18.1` (`ECF` / `THMMNG`), обдув набегающим потоком при вращении колёс и физичный перегрев на месте в отсечке.
3. **Масло `SAE 5W-40` (VFT), двухступенчатый насос `N428` (`1.8 / 3.8 бар`) и топливная система `200 bar GDI`**:
   - Вязкость по Фогелю–Фулчеру–Тамману ($\nu(T)$), гидродинамические потери трения Штрибека–Хейвуда, распыл форсунок `Hiroyasu-Arai SMD`, жидкая топливная плёнка Акино (`Wall-Wetting`) на холодных стенках, вихревые заслонки `Tumble` и поцилиндровый расчёт `1-3-4-2`.
4. **Вращательная инерция коленвала + двухмассового маховика `LuK ZMS` ($J_{\text{eng}} = 0.145\text{ кг}\cdot\text{м}^2$) и колёс `225/40 R18 7.5J x 18 ET51` ($J_{\text{wheels}} = 4.60\text{ кг}\cdot\text{м}^2$)**:
   - Обороты двигателя никогда не меняются скачком за 0 мс: переключение `D (760 RPM) <-> S (840 RPM)`, прогревочные обороты, сброс газа и переключения `K1 <-> K2` интегрируются через момент инерции маховика.
5. **Механическая прочность и фатальные отказы ДВС («мотор может пристрелиться / лечь»)**:
   - **Разрушение перегородок поршня Цилиндра 3 (`P030300 [15129]`)**: при жёсткой детонации (`max_knock_retard_deg >= 5.5°` / `knock_margin_deg < -1.0°`) или бедной смеси под наддувом (`lambda > 1.02` при `boost > 0.75 bar`).
   - **Тепловой прихват поршней и задиры цилиндров**: при перегреве днища поршня (`> 390..415 °C`) или ОЖ (`> 134..139 °C`).
   - **Проворот шатунных вкладышей (`P052400 [16491]`)**: при срыве масляного клина `SAE 5W-40` от перегрева масла (`> 136..158 °C`, вязкость `< 4.5 сСт`) или падении давления масла на высоких оборотах.
   - **Обрыв вала турбины `IHI IS12` (`P029900 [15345]`)**: при раскрутке ротора свыше `192 000..218 000 об/мин` или `EGT > 1000 °C`.
   - Кнопка **`🔄 Полный сброс с нуля`** (`reset_full_simulation`) полностью восстанавливает новый холодный мотор (`100%` ресурс, `+5.0 °C`, `0 ошибок`).
